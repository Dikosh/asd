# Ovi — биржа грузов и транспорта

Платформа, где заказчики и перевозчики находят друг друга напрямую: размещают грузы и транспорт, откликаются, договариваются в чате и ведут рейс с GPS на карте. Интерфейс на русском, казахском и английском, рассчитан на телефон и компьютер.

До 20.11.2026 продукт назывался Jolda. Название заменено во всех текстах сайта, уведомлениях, SMS и боте; служебные имена на сервере остались прежними и на работу не влияют: папка `/opt/jolda`, настройки `/etc/jolda.env`, служба `jolda`, база `jolda.db`, копии в `/var/backups/jolda`.

Продукт собран по двум исходным документам («Функциональное описание платформы для логистики» и «Логистикалық платформаның негізгі функциялары») и закрывает возможности, которые есть у Della и Fa-Fa.kz.

## Запуск

Нужен Node.js 22.13 или новее. База данных — встроенный SQLite, отдельно ставить ничего не надо.

```bash
npm install
npm run build   # собирает интерфейс
npm run demo    # http://localhost:3000 — демо-режим с готовыми данными
```

`npm start` запускает боевой режим: без демо-данных и входа одним нажатием, коды входа уходят только через подключённого SMS-провайдера.

При первом запуске в демо-режиме база заполняется примерами: 16 компаний, около 65 объявлений, история рейсов с отзывами и активный рейс с GPS-треком. На экране входа есть кнопки «Демо-доступ» — вход одним нажатием под заказчиком, перевозчиком, логистом, брокером, водителем или модератором.

Для разработки: `npm run dev` (API на :3000, интерфейс с горячей перезагрузкой на :5173).

В Docker:

```bash
docker build -t jolda .
docker run -p 3000:3000 -v jolda-data:/data -e DEMO_MODE=1 -e DEMO_CONFIRM=1 -e INSECURE_COOKIES=1 jolda   # демо на своём компьютере
```

### Чем сильнее конкурентов

- **Подбор «по пути».** Машина находится, даже если города заказчика — промежуточные точки её маршрута; под каждое объявление платформа сама подбирает встречные и показывает процент совпадения.
- **GPS привязан к сделке и не требует трекера.** Рейс создаётся из принятого отклика; позицию передаёт телефон водителя, экран при этом не гаснет. Без включённого GPS рейс не начать.
- **Контакты бесплатны.** Платные только дополнительные возможности: поднятие в топ и тариф Pro.
- **Репутация до сделки.** Индикатор, отзывы, документы и чёрный список видны прямо в отклике; о рискованном контрагенте платформа предупреждает.
- **Рейтинг трудно накрутить и трудно сломать.** Доставку можно отметить только с GPS у пункта выгрузки и не раньше, чем машина могла доехать; отзывы скрыты, пока их не оставят обе стороны; в рейтинге и индикаторе учитываются отзывы и записи чёрного списка только от проверенных компаний, от каждой — один отзыв; «зелёной» может стать только проверенная компания; запись в чёрный список — только после рейса с этой компанией.
- **Отзыв нельзя пропустить** — рейтинг складывается только из настоящих рейсов.
- **Работает как приложение без магазина.** Сайт ставится на главный экран телефона и присылает push-уведомления.

## Что подключается отдельно

Эти части зависят от внешних договоров и ключей, поэтому в коде сделаны точки подключения, а не имитация:

| Что | Сейчас | Как подключить |
| --- | --- | --- |
| SMS | В демо-режиме код показывается на экране входа; без демо, без провайдера и без бота Telegram вход невозможен | `SMS_WEBHOOK_URL` и `SMS_WEBHOOK_TOKEN`: сервер отправит `POST {phone, text}` (см. `server/sms.js`) |
| Код входа в Telegram | Выключен, пока не задан токен бота | `TELEGRAM_BOT_TOKEN` — см. «Коды входа через бота в Telegram». Бесплатно, договор не нужен |
| Онлайн-оплата | Пополнение баланса работает только в демо-режиме | Подключить платёжного провайдера в `POST /api/balance/topup` |
| Дороги | Расстояние — оценка: прямые отрезки с дорожным коэффициентом 1,22 | `OSRM_URL` — адрес сервера маршрутизации OSRM: расстояние и линия маршрута станут дорожными |
| ЕСУТД | У сотрудника вручную отмечаются статус и номер договора | Автосверка — после получения доступа к API esutd.gov.kz |
| GPS в фоне | Позиция передаётся, пока Ovi открыта на телефоне водителя | Фоновая передача требует приложения из магазина или трекера в машине |
| Магазины приложений | Сайт устанавливается на главный экран (PWA) | Для Google Play сайт упаковывается в Trusted Web Activity; для App Store нужна отдельная сборка |

## Настройки

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | Порт сервера |
| `DATA_DIR` | `./data` | Папка с базой, загруженными документами и ключами push |
| `DEMO_MODE` | выключен | `1` включает демо-данные, вход одним нажатием под любой ролью, код входа на экране и демо-пополнение. Только для показа — не на боевом сервере. После выключения демо все входы, открытые за время демо, закрываются, демо-аккаунты перестают действовать |
| `DEMO_CONFIRM` | выключен | `1` подтверждает демо при `NODE_ENV=production` (стенд для показа). Без него сервер с `DEMO_MODE=1` в боевой конфигурации не запускается |
| `ADMIN_PHONE` | — | Номера модераторов через запятую, например `+77011234567,+77017654321`. Список — единственный источник прав: номер добавили — человек становится модератором (сразу, если уже зарегистрирован, иначе при регистрации), убрали — права снимаются при следующем запуске сервера. Опечатка в номере не даст серверу запуститься |
| `TRUST_PROXY` | выключен | `1`, если сервер стоит за обратным прокси (nginx, облачный балансировщик): тогда адрес клиента берётся из `X-Forwarded-For` |
| `SUPPORT_PHONE`, `TELEGRAM_URL`, `SUPPORT_HOURS` | — | Контакты поддержки: в разделе «Помощь» и на экране входа («Не получается войти?»). Без них человеку, которому не пришёл код, некуда обратиться |
| `SMS_WEBHOOK_URL`, `SMS_WEBHOOK_TOKEN` | — | Отправка кодов входа через вашего SMS-провайдера |
| `REVIEW_LOGIN` | — | Вход для проверяющего из App Store и Google Play: два номера с постоянными кодами, `+77010000001:код,+77010000002:код` (перевозчик и заказчик). SMS на них не уходит, код подходит только к тестовым аккаунтам, между ними всегда есть активный рейс. Номера должны быть свободны: если номер уже зарегистрирован настоящим человеком, постоянный код на нём не действует. Убрать строку и перезапустить сервер — входы закроются |
| `TELEGRAM_BOT_TOKEN` | — | Токен бота от @BotFather: на экране входа появляется кнопка «Получить код в Telegram», коды приходят в чат с ботом. Не путать с `TELEGRAM_URL` — это ссылка на поддержку |
| `BACKUP_REMOTE` | — | Куда каждую ночь отправлять резервную копию (адрес для `rsync`), см. «Сервер: копии и сторож» |
| `SMS_DAILY_MAX` | `300` | Сколько кодов входа площадка отправляет по SMS за сутки; дальше отправка приостанавливается (защита от рассылки за ваш счёт), а модераторы получают уведомление — один раз в сутки. `0` — без предела. Коды в Telegram в этот счёт не входят. Когда людей станет больше, предел нужно поднять |
| `SMS_COUNTRIES` | `7,998,996,992,993,86,375,994,995,90` | Коды стран, на номера которых отправляются SMS (по умолчанию — страны из списка на экране входа). Оставить только Казахстан и Россию — `7`; `*` — любые страны. На Telegram не действует |
| `OSRM_URL` | — | Сервер маршрутизации OSRM для расстояний по дорогам |
| `TILE_URL`, `TILE_ATTRIBUTION` | серверы OpenStreetMap | Подложка карты. Бесплатные серверы OpenStreetMap годятся для показа, для боевой нагрузки подключите поставщика карт (MapTiler, Stadia Maps, 2ГИС и т. п.), например `https://api.maptiler.com/maps/streets-v2/{z}/{x}/{y}.png?key=…` |
| `INSECURE_COOKIES` | выключен | `1` разрешает вход по HTTP при `NODE_ENV=production` — только для показа на своём компьютере |
| `PUSH_CONTACT` | `mailto:support@jolda.local` | Контакт владельца сервиса для push-серверов браузеров |

Перед боевым запуском: не задавайте `DEMO_MODE`, подключите SMS (`SMS_WEBHOOK_URL`) или бота Telegram (`TELEGRAM_BOT_TOKEN`), укажите `ADMIN_PHONE` и `TRUST_PROXY=1`, если есть прокси. Push-уведомления и геолокация работают только по HTTPS. Текст правил платформы (раздел «Помощь → Правила») — рабочий вариант: перед запуском его должен утвердить юрист.

### Коды входа через бота в Telegram

Бесплатная замена SMS: код приходит в чат с ботом. Бот не может написать человеку первым, поэтому при первом входе человек нажимает «Получить код в Telegram», открывает бота и нажимает «Поделиться номером» — Telegram сам подтверждает, что номер принадлежит этому аккаунту. Дальше коды приходят в тот же чат сразу, без лишних нажатий. Если человек удалил или заблокировал бота, при следующем входе ему снова покажут ссылку.

Как подключить:

1. В Telegram написать [@BotFather](https://t.me/BotFather): команда `/newbot`, название (например, «Ovi — коды входа») и имя, оканчивающееся на `bot`. В ответ придёт токен.
2. На сервере дописать в `/etc/jolda.env` строку `TELEGRAM_BOT_TOKEN=…` и выполнить `systemctl restart jolda`. В журнале (`journalctl -u jolda -n 20`) появится строка «Telegram: бот @… выдаёт коды входа».
3. Открыть сайт: на экране входа появилась кнопка «Получить код в Telegram».

Токен — это ключ от бота: не пересылать в чатах и не класть в репозиторий. Если токен попал к посторонним, у @BotFather командой `/revoke` выпускается новый.

У каждого сервера свой бот: два сервера с одним токеном перехватывают сообщения друг у друга, и коды приходят через раз. Сообщения бот получает сам (длинный опрос), домен и HTTPS для этого не нужны. SMS и Telegram работают вместе: если подключены оба, человек выбирает сам; если только Telegram — на экране входа остаётся одна кнопка. Кому Telegram не подходит (нет аккаунта, номер Telegram другой), без SMS войти не сможет.

### Чистый старт боевого сервера

На демо-стенде любой посетитель входил как администратор и мог выдать кому угодно «проверено», баланс и тариф, поэтому настоящим клиентам сервер открывают с пустой базой. Установщик делает это сам:

1. В `/etc/jolda.env` указать `ADMIN_PHONE`, `SMS_WEBHOOK_URL` или `TELEGRAM_BOT_TOKEN` и контакты поддержки.
2. Запустить установщик с `DEMO=0`. Он делает копию, убирает базу и загруженные файлы демо-стенда в `/var/backups/jolda/demo-stand-ГГГГ-ММ-ДД-ЧЧММ/` и запускает сайт с чистой базой. Ключи уведомлений (`vapid.json`, `fcm.json`) остаются на месте.
3. Войти под номером из `ADMIN_PHONE` и убедиться, что в кабинете есть раздел модератора.

Если базу демо-стенда не убрать, сервер без демо-режима не запустится и скажет об этом в журнале. Оставить её осознанно — `DEMO_DATA_KEEP=1` в `/etc/jolda.env`.

Карточки раздела «Заказчики» и новости, заведённые на демо-стенде, вносятся заново. Демо-стенд для показов и боевая площадка на одном сервере не уживаются (общие папки и порт) — для стенда нужен второй сервер.

## Сервер: защита

Установщик `scripts/install-server.sh` при каждом запуске приводит сервер к одному и тому же состоянию:

- **вход на сервер** — только по SSH-ключу (пароль отключается, если ключ уже добавлен); `fail2ban` блокирует адреса, подбирающие вход;
- **брандмауэр** — снаружи открыты только сайт (80, 443) и вход администратора (22); сама программа слушает только `127.0.0.1`;
- **обновления безопасности** ставятся сами — системные, Node.js и веб-сервер Caddy; после обновления Node.js сторож перезапускает сайт;
- **служба сайта** работает под отдельным пользователем `jolda` с ограничениями systemd: пишет только в папку данных, остальная система для неё закрыта;
- **сборка** идёт под пользователем `jolda-build` без прав администратора, установочные скрипты библиотек не выполняются;
- **ключи и данные**: `/etc/jolda.env` читает только root, папку `/var/lib/jolda` — только служба;
- **веб-сервер**: запрос не больше 10 МБ, медленные соединения обрываются, журнал запросов — `/var/log/caddy/timma.log` (10 файлов по 20 МБ);
- **демо → боевой запуск**: при `DEMO=0` база демо-стенда убирается в `/var/backups/jolda/demo-stand-…`, площадка начинает с чистой. Оставить базу осознанно — `DEMO_DATA_KEEP=1` в `/etc/jolda.env`.

Пределы самой площадки (сбор базы, подбор кодов, спам) и то, что ещё не сделано, — в `../docs/security-2026-11-20.md`.

## Сервер: копии и сторож

`scripts/install-server.sh` кроме самого сайта настраивает:

- **ночные копии** в `/var/backups/jolda` (в 03:30, хранятся последние 14): архив `jolda-ГГГГ-ММ-ДД-ЧЧ-ММ.tar.gz` со снимком базы и ключами уведомлений сайта. Действующих входов, кодов и ключа Firebase (`fcm.json`) в копии нет: после восстановления все входят заново, а `fcm.json` скачивается заново в консоли Firebase. Загруженные файлы (документы, фото, ТТН) лежат рядом в общей папке `uploads/` — в неё каждую ночь докладываются только новые, поэтому копии не разрастаются. Сделать копию вручную: `systemctl start jolda-backup`;
- **копии перед обновлением** — `jolda-update-….tar.gz`, последние 5, отдельно от ночных: серия обновлений ночные копии не вытесняет;
- **проверку места**: копия не делается, если после неё на диске останется меньше 500 МБ (`MIN_FREE_MB`);
- **отправку в другое место**: укажите в `/etc/jolda.env` `BACKUP_REMOTE=пользователь@сервер:/папка` (адрес для `rsync`, вход по SSH-ключу root) — ночная копия будет уходить и туда. Без этого копии лежат на том же диске, что и база, и при поломке сервера пропадут вместе с ней. На втором сервере старые копии сами не удаляются;
- **присмотр**: сервер раз в 15 минут смотрит на итог последней копии (`/var/lib/jolda/backup-status.json`) и на свободное место и пишет администраторам в уведомления, если копий нет больше полутора суток, копия не ушла на второй сервер или свободно меньше десятой части диска;
- **восстановление**: `systemctl stop jolda && tar -xzf /var/backups/jolda/<файл> -C /var/lib/jolda && cp -an /var/backups/jolda/uploads/. /var/lib/jolda/uploads/ && chown -R jolda:jolda /var/lib/jolda && systemctl start jolda`;
- **сторож**: раз в минуту проверяет сайт и перезапускает его, если тот не отвечает три минуты подряд (`journalctl -t jolda-watchdog`).

## Устройство

```
server/           API на Express, SQLite через встроенный node:sqlite
  routes/         auth, listings, deals (отклики, чат, рейсы), company (кабинет), extras (уведомления, команда, тариф, инструменты)
  geo.js          справочник мест, расстояния, подбор «по пути», проверка БИН
  data/places.json  города и посёлки (собирается из GeoNames скриптом scripts/build-places.py)
  notify.js, i18n.js  уведомления и их тексты на трёх языках
  seed.js         демо-данные
web/src/          интерфейс на React и TypeScript, карта на Leaflet
  pages/          экраны
  kz.ts, en.ts    переводы (ключ — русская строка)
web/public/sw.js  сервис-воркер для push-уведомлений
tests/            сквозные тесты API
```

Обновления в реальном времени (сообщения, отклики, уведомления, позиция машины) идут через Server-Sent Events.

```bash
npm test                  # сквозные тесты API
npm run i18n              # проверка, что у каждой строки есть казахский, английский и китайский перевод
npm run seed -- --reset   # очистить базу целиком и загрузить демо-данные заново (только для демо-стенда и разработки)
python3 scripts/build-places.py   # пересобрать справочник мест
```

Справочник мест построен на данных [GeoNames](https://www.geonames.org/) (лицензия CC BY 4.0). Карта — © участники OpenStreetMap.
