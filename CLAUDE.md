# Jolda — заметки для работы над проектом

Биржа грузов и транспорта для Казахстана (RU/KZ/EN/ZH). Владелец продукта общается по-русски; отвечать по-русски, просто, без жаргона — партнёры не из IT.

## Как запускать и проверять
- Node.js ≥ 22.13. `npm install`, `npm run build`, `npm run demo` → http://localhost:3000 (демо-данные, вход одним нажатием под любой ролью).
- `npm run dev` — API на :3000 и интерфейс с горячей перезагрузкой на :5173.
- Перед коммитом: `npm test` (API-тесты, запускать с временным `DATA_DIR`), `npm run i18n` (у каждой строки должен быть казахский, английский и китайский перевод), `npm run build` (там же проверка TypeScript).
- Сервер на Ubuntu ставится/обновляется одной командой: `scripts/install-server.sh` (см. комментарий в начале файла). Он же настраивает ночные копии (`scripts/backup.mjs` → /var/backups/jolda: ночные и «перед обновлением» хранятся раздельно, загруженные файлы — общей папкой `uploads/`, `BACKUP_REMOTE` — вторая площадка) и сторожа, который перезапускает зависший сайт. Сервер сам следит за копиями и местом на диске (`server/health.js`) и пишет администраторам.
- Порядок работы: правка в `~/jolda-dev` → тесты, переводы, сборка → коммит и push в `main` → повторный запуск установщика на сервере (`/opt/jolda` установщик перезаписывает — там не править).

## Устройство
- `server/` — Express 5 + встроенный `node:sqlite`. `routes/`: auth, listings (поиск, подбор, рыночная ставка), deals (отклики, чат, рейсы, GPS, ссылка водителя), company (кабинет, документы, модерация), extras (уведомления, команда, тариф, модератор, поддержка).
- `server/lib.js` — общие правила: роли, лимиты, сессии, `parse()` (ошибки проверки по-русски), `companyOut`/`indicator` (репутация), `modLog`.
- `server/db.js` — схема и миграции (`addColumn`), представления `visible_reviews`, `rated_reviews`, `company_stats`. `run`/`insert` повышают `dataVersion()` при записи в listings, trips, companies, reviews, blacklist.
- Поиск, подбор и рекомендации берут активные объявления из памяти (`activePool`/`lightListings` в lib.js, перечитываются при смене `dataVersion`), репутацию — из кэша `companyMap`; полные карточки грузятся только для показываемой страницы (`hydrate`). Писать в эти таблицы — только через `run`/`insert`, иначе поиск не узнает об изменении.
- `server/i18n.js` — тексты уведомлений на трёх языках (для push).
- Push в мобильное приложение — Firebase Cloud Messaging (`server/fcm.js`, без библиотек): токены устройств в `push_devices` (`POST /api/push/device`, `/api/push/device/remove`, не больше 5 на человека), `notify()` шлёт туда тот же текст, что и Web Push, а недействительные токены удаляет. Ключ — файл сервисного аккаунта `FCM_SERVICE_ACCOUNT` (по умолчанию `<DATA_DIR>/fcm.json`, на сервере `/var/lib/jolda/fcm.json`, владелец jolda, права 600); нет файла — push в приложение выключен.
- `web/src/` — React + TypeScript + Vite + Leaflet. Строки интерфейса: `t('русская строка')`, переводы в `kz.ts`, `en.ts` и `zh.ts` (китайский упрощённый; ключ — русская строка).
- `server/data/places.json` — справочник ~6 650 мест (GeoNames), собирается `scripts/build-places.py`; китайские названия — `server/data/places-zh.json` (`scripts/build-places-zh.py`, где нет — показывается английское).

## Правила продукта, которые легко сломать
- GPS — только с телефона водителя (без трекеров). Точки, накопленные без связи, приложение досылает пачкой со своим временем (`POST …/positions`); событие `position` несёт координаты, скорость и остаток пути — экраны обновляются из него, без повторной загрузки рейса. Этапы рейса строго по порядку; «В пути» требует свежую позицию; «Выгрузка» и «Доставлено» — в 80 км от пункта выгрузки и не быстрее, чем можно проехать маршрут (160 км/ч).
- В рейтинг и индикатор идут отзывы и записи чёрного списка только от проверенных компаний; «зелёная» — только проверенная компания. Отзыв и чёрный список — только после состоявшейся сделки (`L.dealDone`): рейс завершён либо сорван после подтверждения перевозчиком; по рейсу, отменённому до выезда, — нельзя.
- Брокера нельзя «принять» как перевозчика. Водитель из команды видит только рейсы, на которые его назначили (без цен, чатов, денег): для него в `server/index.js` разрешающие списки `DRIVER_READ` и `DRIVER_WRITE` — новый маршрут ему закрыт, пока не добавлен туда; события рейса идут сотрудникам и назначенному водителю (`tripUsers`).
- Заблокированная компания (`requireActiveCompany`) не размещает объявления, не откликается, не принимает отклики, не оставляет отзывы и записи в чёрный список; писать в чат может только партнёру, с которым у неё идёт рейс. Отклик заблокированной компании принять нельзя.
- Рейс начинается только после подтверждения перевозчиком: машина, госномер и водитель (`POST /api/trips/:id/assign`). До «В пути» их можно заменить.
- Груз на несколько машин (`listings.trucks`): каждая машина — отдельный рейс. Объявление в поиске, пока идущих и завершённых рейсов меньше, чем машин (`BOOKED` в lib.js); закрывается, когда все рейсы завершены. Сорванный рейс закрывает только объявление на одну машину.
- «Рыночная ставка» считается одной функцией `marketRate` (listings.js) для карточки, «Цен» и калькулятора: сначала направление, потом похожая дальность; короткие и дальние рейсы не смешиваются.
- Отзыв после рейса обязателен, но работа блокируется только через 72 часа без отзыва (`requireNoPendingReviews`: новое объявление, правка и возврат старого, поднятие в топ, отклик).
- Платные действия защищены от повторного нажатия: поднять в топ уже поднятое объявление нельзя, такую же оплату тарифа или карточки услуг сервер принимает не раньше чем через полминуты (`requireNoRecentPayment`).
- Перегон (раздел `/relocation`): заявка — объявление вида `relocation` (что перегнать `vehicle_kind`, нужные права `licenses`), отклик/чат/рейс/GPS/отзыв как у груза; заказчик — автор заявки. При принятии отклика рейс сразу подтверждён, водитель — откликнувшийся перегонщик, госномер не обязателен. Профиль «Я перегонщик» (права, город) — в `users`, `server/routes/relocation.js`; уведомление о заявке — перегонщикам с нужными правами в 150 км от старта. Демо: `node server/seed.js --relocation`. Очистка базы (`seed.js --reset`, функция `wipe`) берёт список таблиц из самой базы — вручную его не вести.
- Каталог услуг (`/services`, `server/routes/services.js`): перегон, сопровождение негабарита, таможенный брокер. Исполнитель создаёт карточку компании и платит за показ с баланса (`L.SERVICE_PLAN`: 5 000 ₸ за 30 дней, продление прибавляется); неоплаченная карточка в каталоге не видна. Заказчики звонят напрямую, нажатия считаются в `services.views`.
- Раздел «Заказчики» (`/shippers`, `server/routes/shippers.js`, таблица `shippers`): крупные компании со своими сайтами заявок, кнопка «Перейти к заявкам» ведёт на их сайт, переходы считаются (кроме админа и демо). Карточки добавляет только администратор и только после договорённости с компанией; пункт меню появляется, когда есть видимая карточка (`meta.stats.shippers`). Дальше — интеграция по API после встреч.
- «Показатели площадки» (кабинет → `metrics`, `GET /api/admin/metrics`): цифры для встреч с заказчиками. По умолчанию без демо-пользователей (`users.is_demo`); активность — по `users.last_seen` (обновляется не чаще раза в час в `loadUser`).
- Файлы в чате и рейсе (`server/files.js`, таблица `files`): тип проверяется по содержимому, отдаются только участникам; удалить нельзя — это подтверждение для обеих сторон. Фото сжимаются в браузере (`prepareUpload`).
- Объявление закрыто любым способом (срок, архив, модератор, все рейсы завершены) — отклики «на рассмотрении» отклоняются (`declineOrphanResponses`, заодно в `housekeeping`).
- Скорость: репутация компаний (`company_stats`) и частые запросы держатся на индексах из `server/db.js`; `tests/ops.test.js` проверяет, что они не перебирают таблицы целиком. Условие «компания — заказчик ИЛИ перевозчик рейса» в представлениях писать двумя подзапросами: с «или» SQLite без статистики может выбрать полный перебор. Замер на большой базе — до правки индексов и после.
- Телефон пользователя, скрывшего его в настройках, нельзя отдавать через API (`phoneFor`).
- Текст ошибки с числом или названием внутри — только `L.tbad(код, 'шаблон с {n}', { n })`: клиент получает шаблон и значения и показывает перевод. Склеенную строку перевести нельзя — `tests/texts.test.js` такие находит. Проверка переводов (`scripts/i18n-keys.cjs`) видит тексты `bad`/`tbad`, `rateLimit(…, 'текст')`, `message: '…'` и `.refine`; новый способ отдать текст пользователю — добавить и туда.
- Язык уведомлений — `users.settings.lang`. Сайт и приложение сами сообщают его серверу после входа и при смене языка (`main.tsx`, `session.dart`): язык, выбранный до входа, сервер иначе не узнает.
- Код входа привязан к тому, кто его запросил (cookie `otp`, таблица `login_codes`), неверные вводы считаются на сам код (5), а не на номер: посторонний не может закрыть чужой вход. Суточные пределы SMS (10 на номер, 300 с адреса, `SMS_DAILY_MAX` на площадку) действуют вне демо; у устройства, с которого под номером уже входили (cookie `kd`, `known_devices`), свой счёт кодов.
- Код входа можно получить в Telegram (`server/telegram.js`, включается `TELEGRAM_BOT_TOKEN`): запрос кода с `via: 'telegram'`. Бот не пишет первым, поэтому первый раз сервер отдаёт ссылку на бота с одноразовой меткой (`login_codes.tg_start`), человек делится своим номером, связка «номер → чат» ложится в `tg_links`, и следующие коды уходят в чат сразу. В обоих случаях ответ несёт `telegramUrl` (ссылка на чат с ботом; клиент показывает кнопку «Открыть Telegram», приложение открывает чат само) и `sent` — код уже в чате или сначала нужно поделиться номером. Код в сообщении бота размечен `<code>`: в Telegram копируется нажатием. Номер принимается только с кнопки «Поделиться номером» (`contact.user_id` равен отправителю) — пересланный чужой контакт не подходит. Срок кода считается от отправки в чат, а не от запроса. Клиенты узнают о способах входа из `meta.login` (`sms`, `telegram`). Предел `SMS_DAILY_MAX` считает только SMS (`login_codes.channel`), остальные пределы общие. Тексты бота — в самом `telegram.js` на четырёх языках (язык из настроек Telegram), в общий словарь переводов они не входят. Бот работает длинным опросом: один токен — один сервер.
- Сообщение в чате в список уведомлений не пишется: о нём уходит только push (`pushOnly` в `server/notify.js`) — в мобильное приложение и в браузер, где сайт закрыт (`L.openSessions`). Пачка сообщений подряд — один push, пока собеседник не открыл переписку или не прошло 3 минуты (`pushMessage` в deals.js). Сообщение, у которого уже есть своё уведомление (текст отклика), отправляется с `silent`.
- Модераторы — номера из `ADMIN_PHONE` через запятую; при запуске права приводятся к этому списку (`syncAdmins` в auth.js): лишним снимаются, демо-аккаунты не затрагиваются. Без `ADMIN_PHONE` права не меняются. О заявке на проверку компании, жалобе, обращении и сорванном рейсе модераторы получают уведомление.
- Закрывать вход — только через `L.dropSessions`: вместе с сессией удаляются её push-подписки и устройства (`sid`) и закрываются потоки событий (событие `logout`).
- Демо-режим включается только `DEMO_MODE=1`; в `NODE_ENV=production` ещё нужен `DEMO_CONFIRM=1`, иначе сервер не запускается. Установщик включает демо только при `DEMO=1` и при обновлении сохраняет прежний выбор; домен он тоже берёт из прошлой установки (снять — указать `none`). Вход живёт 30 дней с последнего использования (`sessions.used_at`, продление в `loadUser` не чаще раза в сутки). Вне демо сессии демо-аккаунтов не действуют (`loadUser`), а при первом запуске после демо все сессии и push-устройства удаляются (`leaveDemoMode`, отметка в `app_state`).

## Открытые вопросы и планы (на 17.11.2026)
- Ролевые интерфейсы: сейчас у ролей почти одинаковый функционал, предложено сделать отдельные экраны для заказчика, перевозчика, логиста, брокера, водителя.
- Приложение водителя для Android с передачей GPS в фоне (браузер передаёт только при открытой странице).
- ТТН и путевой лист из данных рейса; позже отправка в ЕСУТД (esutd.gov.kz, Минтранс) — кандидат на подключение: прокси-API Smart Cargo. Обязательная регистрация в ЕСУТД отложена до 01.06.2027.
- Вход по ЭЦП (NCALayer, без госразрешений) и через eGov Mobile (нужно подключение через SmartBridge).
- HR: найм водителей и логистов. Рассылка новых грузов в Telegram/WhatsApp. Безопасная сделка, факторинг, страхование — как источники дохода.
- Для боевого запуска: SMS-провайдер (`SMS_WEBHOOK_URL`) или бот Telegram для кодов входа (`TELEGRAM_BOT_TOKEN`), поставщик карт (`TILE_URL`), сервер в Казахстане, юрист для правил.
